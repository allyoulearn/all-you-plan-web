# All You Plan — Sub-project 5: Wren (AI Coach) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Checkbox (`- [ ]`) steps.

**Goal:** Bring the Wren coach to life — the chat surfaces (web side panel + full chat screen; mobile Wren tab + sheet), the Daily review wizard, and the coach's reply behavior.

**Design decision — how Wren is powered:** scripted / rule-based, not an LLM. Wren's replies are generated server-side by a small keyword-intent matcher returning warm, contextual canned text (the design prototype itself used canned replies). This needs no API key, no per-message cost. A real LLM is a clean future swap (the reply service is a single function) but is out of scope. Conversations are stored (the API's `wren` domain).

**Architecture:** Part A adds the reply service to the existing `wren` API domain. Parts B/C build the UI on the Foundation primitives + the SP2/SP3/SP4 store/operations pattern. The Foundation already built the *chrome* of the web Wren panel (`WrenPanel.vue`) and the mobile Wren sheet (`WrenSheet.tsx`) — this sub-project fills them with the live conversation.

**API contract** (built — `2026-05-21-sp2-api.md` Task 8): `wrenMessages` → `[WrenMessage { id sender text actions createdAt }]`; `sendWrenMessage(text)` → `WrenMessage`. Review domain (Task 7): `dailyReview(date)` → `DailyReview`; `saveDailyReview(date, mood, responses)`.

**Design reference:** the Claude Design bundle — `ai-panel.jsx` (the always-on Wren panel: header, message bubbles, input, quick-prompt chips), desktop `screens.jsx` Chat screen and Daily review (a 4-step wizard: mood / what moved / what didn't / Wren's send-off); mobile `mobile.jsx` `MWrenScreen`, `MWrenSheet`, `MReviewScreen`.

Work on `main`, one commit per task.

## Part A — API (`all-you-plan-api`)

### Task A1: Wren reply service
**Files:** Create `src/domains/wren/service.ts`, `src/__tests__/wren.test.ts`; modify `src/domains/wren/resolvers.ts`.
- [ ] Create `wren/service.ts` exporting `generateWrenReply(userText: string): { text: string; actions: string[] }`. Lowercase the input and match keyword intents, each returning a warm canned coach reply + 0–3 action labels:
  - `plan` / `focus` / `today` → a focus-suggestion reply, actions `['Plan tomorrow', 'Show today']`.
  - `overwhelm` / `stuck` / `too much` → a reassuring reply, actions `['Pick one thing']`.
  - `project` / `memoir` / `progress` → a project-encouragement reply, actions `['Open projects']`.
  - `tired` / `rest` / `done` → a permission-to-rest reply, no actions.
  - greeting (`hi`, `hello`, `hey`, `morning`) → a warm greeting, actions `['What should I focus on?']`.
  - fallback (no match) → an honest "I can't dig into that yet, but…" reply, actions `['What should I focus on?', 'Plan tomorrow']`.
- [ ] Modify `wren/resolvers.ts` — `sendWrenMessage(text)` now: stores the `user` message, calls `generateWrenReply`, stores the resulting `coach` message (with its `actions`), and **returns the coach message**. (`wrenMessages` is unchanged.)
- [ ] Create `src/__tests__/wren.test.ts` — unit-test `generateWrenReply`: an "I'm feeling overwhelmed" input yields the reassuring intent; an unmatched input yields the fallback with 2 actions.
- [ ] Run `npm test` (passes) + `npx tsc --noEmit`; commit `feat: wren scripted reply service`.

## Notes
- The Today screen's "Plan with Wren" button (web) and the coach card stay simple — opening Wren is enough; no deep context-passing this sub-project.
- Quick-prompt chips are static strings that fill the input draft (they do not auto-send), matching the design.
- `generateWrenReply` is intentionally a single pure function — swapping in a real LLM later means changing only that function and (optionally) making the resolver async over a network call.
